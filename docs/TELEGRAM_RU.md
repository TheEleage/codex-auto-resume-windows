# Telegram для Codex Auto Resume

Ветка feature/telegram-notifications добавляет необязательный канал уведомлений Telegram в Windows Dashboard: **Настройки → Общие → Telegram-бот**.

## Настройка

1. Создай бота через @BotFather и открой с ним чат.
2. Получи числовой Chat ID. Для группы или канала добавь бота и дай ему право отправлять сообщения.
3. Открой Dashboard → Настройки → Общие → Telegram-бот.
4. Нажми **Загрузить настройки**. Это покажет состояние сохранённого подключения, не раскрывая токен.
5. Укажи токен, Chat ID, включи канал и нажми **Сохранить Telegram**.
6. Нажми **Проверить связь** и дождись тестового сообщения.

Токен хранится в config/telegram.json только в зашифрованном виде через Windows DPAPI (CurrentUser). Он не появляется в общих настройках, логах или исходниках GitHub. При последующем сохранении оставь поле токена пустым, чтобы сохранить прежний.

**Русский** можно выбрать в общей настройке языка интерфейса. Ранее выбранный язык приложения не перезаписывается. Telegram-сообщения всегда русские.

## Какие события приходят

Telegram наследует включённые типы уведомлений из общей секции приложения. Если отключить уведомление в программе, оно перестанет отправляться в Telegram. Отдельный переключатель Telegram по умолчанию выключен.

События включают прерывание из-за лимита, ожидаемое время восстановления, попытку продолжения, результат восстановления, ошибку и необходимость твоего участия.

Уведомление «Когда требуется моё участие» **по умолчанию отключено в самом Auto Resume**. Чтобы получать его в Telegram, сначала включи его в общих уведомлениях. Служебные предупреждения о питании ПК Windows продолжает показывать по своим правилам, но Telegram не отправляет их, если отключён общий переключатель уведомлений.

В Telegram не отправляются тексты задач, цели, ответы Codex или пути к проектам. Но отправляется идентификатор беседы, если он известен. Используй доверенный чат.

Отправка идёт в отдельном фоне с сетевым тайм-аутом; сбой Telegram не останавливает восстановление задач. Повтор потенциально доставленного сообщения автоматически не производится.

## Проверка

В каталоге исходников на Windows с Python 3.12 или новее:

```powershell
$env:PYTHONPATH = "src"
python -m unittest discover -s tests -p test_telegram_mirror.py -v
python -m unittest discover -s tests -p test_telegram_dpapi_windows.py -v
python -m unittest discover -s tests -p test_privacy_claims.py -v
```

Второй набор использует **настоящий Windows DPAPI**, но только синтетический токен
и временный каталог. Он не связывается с Telegram. Дополнительные проверки
интерфейса, архитектуры и сборки запускаются в GitHub Actions:
[Telegram integration checks](https://github.com/TheEleage/codex-auto-resume-windows/actions).

Кнопка **«Проверить связь»** — отдельное действие: она отправляет одно тестовое
сообщение через Telegram Bot API и передаёт туда токен бота и Chat ID.
Она не запускает и не возобновляет задачи Codex. Токен и Chat ID сначала нужно
сохранить. Ответ API подтверждает принятие сообщения, но не чтение человеком.

[Предварительные ZIP и установщики Standard/Advanced](https://github.com/TheEleage/codex-auto-resume-windows/actions)
публикуются исключительно в артефактах CI; это **не релизы**.
До успешной полной матрицы тестов, генерации новых скриншотов и проверки
с настоящим ботом устанавливать их вместо рабочей версии не рекомендуется.

## Ограничения

- Команды управления из Telegram не реализованы.
- Goal Continuation в этой ветке не менялся.
- Нет гарантии прочтения человеком, только подтверждение API Telegram.
- Есть предварительные установщики Windows из GitHub Actions, но стабильный релиз форка ещё не опубликован.
- Сброс обычных настроек не удаляет токен; канал отключается отдельно. При полной очистке данных файл Telegram удаляется.
